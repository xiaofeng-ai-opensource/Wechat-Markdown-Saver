## 2. 根因修复：隐藏页面终于会被创建

- 补 `offscreen` 权限后，`chrome.offscreen` 不再 `undefined`，`ensureOffscreenDocument()` 的提前返回消失——v2.2.0 那套「用隐藏页面持有句柄」的修复首次真正生效。
- 修就绪竞态：先注册 `OFFSCREEN_READY` 监听、再 `createDocument`；用 `getContexts()` 判断文档是否已存在（旧版回退 `clients.matchAll`）。
- 隐藏页面不再调用 `chrome.storage.local`（该上下文受限）：文件夹名从 `dirHandle.name` 取。
- 隐藏页面不再尝试无手势的 `requestPermission()`：权限非 `granted` 时返回 `PERMISSION_EXPIRED` / `PERMISSION_DENIED`，交回有手势的页面处理。

## 3. 状态与结果分层

- 配置不再被临时失败抹掉：全项目删标记调用只剩设置页「清除」按钮一处。
- 三态显示：未配置 / 需重新授权（橙）/ 已就绪（绿），弹窗与设置页一致。
- 结构化结果：写成功才 `{done:true}`；失败为 `degraded`（带 code、reason、next、zip 文件名），zip 完成一次性发出，不被进度消息覆盖。

## 5. 浏览器内实测（待用户执行，本环境无法装载扩展）

验收清单见 `docs/方案-免重选文件夹与失败可见.md` 第 7.1 节。重点四项：

1. 正常保存 → 真写进文件夹、弹窗「已保存」、绿色角标。
2. 完全关闭浏览器再打开、直接保存 → 最多弹一次授权确认、不出现目录选择框、写入成功。
3. 手动撤销权限后点保存 → 弹窗提示「未写入 + 原因 + 下一步」；点「重新授权」恢复后写入成功；设置页文件夹名不丢。
4. 快捷键在权限失效时保存 → 红色角标 + 自动打开设置页，不再静默。

> **新增实测证据（2026-11-23 22:13，Edge 156）**：在设置页点「重新授权」后，Edge 弹出三选一授权框（「本次允许 / 每次访问都允许 / 不允许」），显示的是已存的 `AI开源求索` 文件夹，**没有出现目录选择框**。这确认了 R1（扩展页面可弹三选一）成立；D2 的「一键恢复、不重选目录」路径已可见。仍需点选其中一项并回文章页完成一次保存，才能判定整个链路成功。

### 5.1 后续 UI 修复：状态行不再与文件夹行矛盾（22:21）

- **现象**：重开 Edge 后，顶部文件夹行显示橙色「需重新授权」，中间状态行却仍是灰色「就绪」。
- **根因**：`popup.html:30` 的 `#status-text` 写死 `popupReady`；`popup.js` 初始化只在「非文章页」时调用 `setState('not-article')`，文章页分支从不设置状态，于是静态「就绪」一直保留。
- **改动**：`popup.js` 的 `setState()` 新增 `needs-auth` / `unconfigured` 两态；`onI18nReady` 初始化时按 `folderState` 主动设置状态行（文章页也会同步）；`popup.css` 新增 `.status-text.needs-auth`（橙色，与文件夹行一致）。复用现有文案键 `popupFolderNeedsAuth` / `popupFolderNoSet`，未新增文案。
- **验证**：`node --check` 通过；三端重新打包后 `dist/{chrome,edge,firefox}/popup/` 的 JS/CSS 均含该修复且语法有效。浏览器内视觉验收待用户重新加载扩展后确认。

> **新增实测证据（2026-11-23 22:18，Edge 156）**：上次在授权弹窗选的是「本次允许」，完全关闭 Edge 再打开后，弹窗顶部显示橙色「AI开源求索 · 需重新授权」。这一条同时验证了三件事：①「本次允许」确实不跨浏览器会话；②三态显示生效（橙＝需重新授权）；③文件夹配置未被删（名字仍在）。这正是保底档的预期表现。用户追问「如何选才能重启后不再提示」，答案是弹窗第二项「每次访问都允许」（Chrome/Edge 122+ 持久授权），选后需再重启一次实测确认。
