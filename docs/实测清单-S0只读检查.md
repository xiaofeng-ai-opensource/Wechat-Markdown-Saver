## 0. 先对齐「只读」的边界

这一轮要确认的是**方案的前提有没有站住**，不是修问题。当前环境无法把扩展装进真实浏览器，所以打开页面、点按钮、看弹窗这些动作要由你在自己的 Chrome 或 Edge 里做；我能做的是把地址、命令、判定口径和回填表备齐。

**允许**：打开页面、看权限列表、看控制台日志、在控制台执行查询类代码、观察浏览器授权弹窗。

**禁止**（会改变现状，影响后续判断）：

- 不点「保存到文件夹」、不按 `Ctrl+Shift+S`（会写文件或下载压缩包，还会清掉显示标记）；
- 不点设置页的「选择文件夹」「清除」；
- 不执行 `chrome.storage.local.set` / `remove`、不删 IndexedDB 里的值；
- 不点「删除站点数据」；
- 不调用 `verifyHandleUsable()`（它会创建再删除临时文件）。

**唯一可能改变状态的一步**：第 5 页的「临时授权按钮」会触发浏览器授权弹窗。看到弹窗先截图；选哪一项由你决定，按 Esc 取消也可以。它不改代码、不写文章文件。

**先记三项基础信息**（后面每一页都要用到）：

| 项 | 从哪拿 | 为什么需要 |
|---|---|---|
| 扩展 ID | `chrome://extensions` 开「开发者模式」后复制 | 拼扩展页面地址 |
| 浏览器版本 | `chrome://version`（Edge 为 `edge://version`） | 只有 122 以上才有「每次访问都允许」三选一 |
| 扩展版本与加载路径 | `chrome://extensions` 该扩展卡片与「详细信息」 | 确认测的是当前 2.2.0 源码，不是旧构建 |

下文所有 `<ID>` 都替换成实际扩展 ID。

## 2. 公共查询代码（P3–P6 通用，纯查询）

在任一扩展页面的控制台先粘贴这段，再执行 `await wmsRead()`。它只读数据库与设置区，不创建库、不写值、不申请许可：

```js
async function wmsRead() {
  const dbs = await indexedDB.databases();
  if (!dbs.some(d => d.name === 'wechat-md-saver')) {
    console.log('库 wechat-md-saver 不存在：从未选过文件夹，或数据被清过');
    return null;
  }
  const db = await new Promise((res, rej) => {
    const r = indexedDB.open('wechat-md-saver');
    r.onsuccess = () => res(r.result);
    r.onerror = () => rej(r.error);
  });
  const h = await new Promise((res) => {
    if (!db.objectStoreNames.contains('handles')) return res(null);
    const r = db.transaction('handles', 'readonly').objectStore('handles').get('dirHandle');
    r.onsuccess = () => res(r.result || null);
    r.onerror = () => res(null);
  });
  let perm = 'NO_HANDLE';
  if (h) {
    try { perm = await h.queryPermission({ mode: 'readwrite' }); }
    catch (e) { perm = 'QUERY_THREW: ' + e.name + ' ' + e.message; }
  }
  const s = await chrome.storage.local.get(null);
  console.table([{
    句柄名: h ? h.name : null,
    类型: h ? h.kind : null,
    写入许可: perm,
    folderSet: s.folderSet ?? null,
    folderName: s.folderName ?? null,
    扩展版本: chrome.runtime.getManifest().version
  }]);
  return { h, perm, s };
}
await wmsRead();
```

`写入许可` 的三种正常取值：`granted`（可用）、`prompt`（要重新授权）、`denied`（被拒）。若出现 `QUERY_THREW`，把整段报错记下来——后台服务里代码本来就没用这个接口，而是用试写文件代替，这个结果正好解释原因。

## 3. 逐页检查项

### P1 · 扩展管理页与扩展详情

1. 开「开发者模式」，复制 ID；确认版本 `2.2.0`、加载路径是 `C:\ai-workspace\Wechat-Markdown-Saver`（或 `dist/chrome`），**不是旧构建目录**。
2. 「详细信息」→ 权限列表：找有没有 `offscreen` 字样。三份清单的 `permissions` 都是 `activeTab / downloads / storage / unlimitedStorage / debugger`，没有 offscreen。
3. 「检查视图」下拉：记下有哪些可检查的页面（后台服务、设置页、隐藏页面等）。
4. 点「错误」（Errors）看有没有 `Failed to create offscreen document`、`Offscreen write failed: NO_FOLDER`、`Direct write failed` 之类的记录。

对应：**R5**、方案第 3 节 P0。

### P2 · 版本页

记下完整版本号与内核版本，例如 `Chrome 131.0.x`。低于 122 直接判 R1 不成立，路径 A（持久授权）不用测，交付承诺按保底档。

### P3 · 后台服务控制台（最关键，四条查询）

依次执行，每条都把输出贴回第 4 节表格：

```js
typeof chrome.offscreen
```

```js
await chrome.runtime.getContexts({});
```

```js
try { console.log('PING:', await chrome.runtime.sendMessage({ action: 'PING' })); }
catch (e) { console.log('PING 失败:', e.message); }
```

```js
await wmsRead();
```

判定口径：

| 观察 | 说明 |
|---|---|
| `typeof chrome.offscreen` 为 `undefined` | `ensureOffscreenDocument()` 会直接返回 false，整套隐藏页面逻辑从未运行；后台退回试写直写路径，P0 坐实 |
| `getContexts` 里没有 `OFFSCREEN_DOCUMENT` | 隐藏页面没被创建（或已被回收） |
| `PING` 返回 `{pong:true}` | 隐藏页面确实活着；报错或 `undefined` 说明没有接收者 |
| `getContexts` 用不了（旧版浏览器） | 记下报错，改用「检查视图」列表 + PING 判定 |

> 说明：`PING` 是项目里已有的只读消息，隐藏页面收到只回一个 `pong`，不改任何状态。`CHECK_HANDLE` **不要用来做只读探针**——它内部会走 `loadDirectoryHandle()`，在许可为 `prompt` 时会尝试一次 `requestPermission()`（无手势、必然失败被吞掉），不是纯查询。

对应：**R5**、P0、P4（快捷键零反馈的上下文）。

### P4 · 设置页（R1 与 R3 的主测场）

地址：`chrome-extension://<ID>/options/options.html`，按 F12 打开控制台。

基础三项：

```js
typeof window.showDirectoryPicker
await wmsRead();
await chrome.storage.local.get(null).then(d => console.table(d));
```

再记录界面上「保存文件夹」那一行显示的是「未选择」、文件夹名、还是「(expired)」——与 `wmsRead()` 的结果对照，验证「显示标记被删、凭证还在」这个现状。

**临时授权按钮（会弹浏览器授权框，先截图再决定）**：粘贴下面这段，然后**用鼠标点页面上出现的按钮**，不要在控制台里调用 `.click()`（那样没有真人手势）：

```js
(async () => {
  const r0 = await wmsRead();
  const h = r0 && r0.h;
  if (!h) return console.log('没有句柄，跳过授权测试');
  const mk = (label, handler) => {
    const b = document.createElement('button');
    b.textContent = label;
    b.style.cssText = 'position:fixed;z-index:99999;padding:10px 14px;background:#07c160;color:#fff;border:0;border-radius:6px;font-size:14px';
    b.onclick = handler;
    document.body.appendChild(b);
    return b;
  };
  const a = mk('A 预读凭证后申请（S0）', async () => {
    console.log('A 点击前:', await h.queryPermission({ mode: 'readwrite' }));
    try { console.log('A 申请结果:', await h.requestPermission({ mode: 'readwrite' })); }
    catch (e) { console.log('A 抛错:', e.name, e.message); }
    console.log('A 点击后:', await h.queryPermission({ mode: 'readwrite' }));
  });
  a.style.top = '8px'; a.style.right = '8px';
  const b = mk('B 点击内读库后申请（S0）', async () => {
    const r = await wmsRead();
    if (!r || !r.h) return console.log('B 无句柄');
    try { console.log('B 申请结果:', await r.h.requestPermission({ mode: 'readwrite' })); }
    catch (e) { console.log('B 抛错:', e.name, e.message); }
  });
  b.style.top = '56px'; b.style.right = '8px';
  console.log('两个按钮已插入，请用鼠标分别点击');
})();
```

要点：

- **按钮 A** 模拟方案主路径（凭证预先读进内存，点击时直接申请）。看弹窗是普通「允许」还是**三选一「仅此次允许 / 每次访问都允许 / 不允许」** → 这是 **R1** 的判定。
- **按钮 B** 在点击里才异步读数据库，验证 **R3**（用户手势在异步等待后是否还有效）。若 B 抛 `SecurityError` 而 A 成功，方案里「弹窗打开时预读凭证」这一步就是必须的。
- 若当前许可已是 `granted`，`requestPermission()` 不会弹窗。想测三选一，先完全退出浏览器再打开（多数会话结束会掉回 `prompt`）；若重启后仍是 `granted`，说明可能已经是持久授权，这本身是要记的重要结果。
- 弹窗截图要能看清三个选项；选完再执行一次 `await wmsRead()` 记录新许可值。

对应：**R1、R3**，决定 **D2、D11**。

## 5. 结果怎么收敛到决策

| 实测结论 | 对方案的影响 |
|---|---|
| `chrome.offscreen` 不存在 / 没有隐藏页面上下文 | **D1 必须选②或③**：先修前置，否则权限层改造落在一条没启用的链路上 |

| 三选一弹不出，或浏览器低于 122 | **D2 收敛到 B**，交付承诺改为保底档；方案文档第 2.1 节的强档描述删掉 |

| 授权后隐藏页面仍是 `prompt` | **R2 不成立**，路径 B 要改成「授权与写入放同一页面」或重新评估架构，方案需回到讨论 |

| 重启后许可仍是 `granted` | 说明已有持久授权在生效，记录并据此简化 D11 |

### 6.2 能下与不能下的结论

**已经能下**：

- 浏览器是 Edge 156，远高于 122，三选一弹窗的版本条件满足（前提是扩展页面确实支持，仍需 R1 实测）。
- 设置页与弹窗页此刻都显示「AI开源求索」，设置页写「已就绪」，说明 `folderSet` / `folderName` 目前还在，不是「未设置」状态。
- 图 5 的「不是微信公众号文章」是把弹窗当标签页打开的预期现象，不影响权限与存储检查，不用处理。
- **强信号**：检查视图里没有 `offscreen.html`，说明隐藏页面很可能从未被创建（或已被回收且未列出）。这与「清单权限没写 offscreen」的疑点方向一致。

**还不能下**：

- **不能据图 1 判定 `chrome.offscreen` 不存在**。详情页权限列表通常只列用户可见权限，内部接口权限不在这张列表上；「列表里没有」不等于「接口不存在」。必须用 `typeof chrome.offscreen` 与上下文查询坐实。
- 检查视图不列出隐藏页面文档，也不等于它一定没创建；`getContexts` 与 `PING` 才是判定依据。
- R1（三选一）、R2（跨页面许可共享）、R3（异步读库后手势）、R5（隐藏页面能否用扩展存储区）全部**仍未测**。

### 6.3 下一步最小操作：一次粘贴出齐关键结果

在图 3 那个后台服务控制台里，把下面这一整块粘贴进去回车。纯查询，不点保存、不弹授权框、不改任何数据：

```js
(async () => {
  console.log('A chrome.offscreen =', typeof chrome.offscreen);
  try { console.log('B 上下文 =', await chrome.runtime.getContexts({})); }
  catch (e) { console.log('B 查询失败 =', e.message); }
  try { console.log('C PING =', await chrome.runtime.sendMessage({ action: 'PING' })); }
  catch (e) { console.log('C PING 失败 =', e.message); }
  console.log('D 本地设置 =', await chrome.storage.local.get(null));
  const dbs = await indexedDB.databases();
  if (!dbs.some(d => d.name === 'wechat-md-saver')) {
    console.log('E 数据库不存在：从未选过文件夹或数据被清过');
    return;
  }
  const db = await new Promise(res => {
    const r = indexedDB.open('wechat-md-saver');
    r.onsuccess = () => res(r.result);
    r.onerror = () => res(null);
  });
  if (!db || !db.objectStoreNames.contains('handles')) {
    console.log('E 库在但没有 handles 表');
    return;
  }
  const h = await new Promise(res => {
    const r = db.transaction('handles', 'readonly').objectStore('handles').get('dirHandle');
    r.onsuccess = () => res(r.result || null);
    r.onerror = () => res(null);
  });
  console.log('E 句柄名 =', h ? h.name : null, '类型 =', h ? h.kind : null);
  if (h) {
    try { console.log('F 写入许可 =', await h.queryPermission({ mode: 'readwrite' })); }
    catch (e) { console.log('F 许可查询失败 =', e.name, e.message); }
  }
})();
```

把 A–F 六行输出截图发回即可。判定口径见第 3 节 P3 与第 5 节收敛表。

## 7. S0 实测结果（2026-11-23 21:24，用户回传截图）

### 7.1 原始输出（后台服务控制台）

```
A chrome.offscreen = undefined
B 上下文 = [{…}, {…}, {…}]                       （3 个，未逐项展开）
C PING 失败 = Could not establish connection. Receiving end does not exist.
D 本地设置 = {folderName: 'AI开源求索', folderSet: true, outputStructure: 'obsidian'}
E 句柄名 = AI开源求索 类型 = directory
F 写入许可 = granted
```

### 7.2 结论：找到最上游的根因

| 证据 | 结论 |
|---|---|
| A：`chrome.offscreen = undefined` | 接口在该扩展的后台服务里**根本不存在**。三份清单都没声明 `offscreen` 权限，后台 `ensureOffscreenDocument()` 的 `if (!chrome.offscreen) return false` 会直接返回 false |
| C：`PING` 失败、无接收者 | 隐藏页面没有被创建——这是 A 的直接后果，不是独立故障 |
| 图 6：检查视图无 `offscreen.html` | 同样是 A 的直接后果 |
| B：3 个上下文，无隐藏页面文档 | 与 A、C 一致（未逐项展开，但已足够判定） |

**连起来的因果链**：清单缺 `offscreen` 权限 → 接口不存在 → 隐藏页面从未创建 → v2.2.0 那套「用隐藏页面持有句柄、避开后台服务回收」的修复**完全没有生效** → 保存一直走后台服务直写这条本想废弃的路径。

这把问题从「浏览器把许可收回了」推进到「**修复代码从来没跑过**」。R5 判定为**成立**；P0 从「待实测疑点」升级为**已坐实的最上游根因**。

### 7.3 一项被推翻的旧假设

F：`queryPermission()` 在后台服务里**可以正常调用并返回 `granted`**。因此旧代码里「后台服务查不了许可，只能用试写文件代替」的假设不成立（`service-worker.js:54-66` 的 `verifyHandleUsable()` 属于不必要的复杂化）。这条也说明：当前句柄、显示标记、写入许可三者都是完好的，**此刻直接保存应该能写进文件夹**。

### 7.4 对方案的影响（需要重新拍板的部分）

1. **D1（范围）中的前置修复从「可选」升级为「必须」**：不解决 offscreen 接口缺失，任何基于隐藏页面的改造都落不了地。
2. **新增 D0（写入主体路线）**，这是本次实测带出来的新分岔：
   - **路线甲：补 `offscreen` 权限、启用隐藏页面**，按原方案在弹窗/设置页做授权，由隐藏页面写入。符合原设计意图，但引入竞态、存储限制、生命周期等额外复杂度，且需要完整回归测试。
   - **路线乙：放弃隐藏页面，删除整套分支，统一走后台服务直写**，授权仍放在弹窗/设置页的真人点击上。改动更小、路径单一；实测已证明后台服务能读句柄、能查许可，技术上可行。代价是偏离 v2.2.0 的原设计意图，需要确认它对「后台服务被回收」的抵抗力。
3. **D2（长期可用路径）方向不变**：无论哪条路线，后台服务与隐藏页面都没有用户手势，重新申请许可必须放在弹窗/设置页的真人点击上。
4. **R1（三选一）/ R3（异步读库后手势）仍未测**：它们不再阻塞路线选择；但如果继续不测，「重启后零交互」的强档就不能写进交付承诺，只能承诺保底档。

### 7.5 更新后的收敛映射

| 实测结论 | 决策影响 |
|---|---|
